# 스테이지 기획

2026-09-24 정의.

## 용어

| 용어 | 뜻 |
|---|---|
| 웨이브 | 크립(적)이 한 차례 출몰하는 단위 |
| 스테이지 | 맵 하나에서 웨이브 **15단계**를 치르는 한 판 |
| 보스 스테이지 | 보스가 나오는 별도 스테이지. 일반 스테이지 3개마다 1개. 일반 스테이지에는 보스가 없다 |
| 저장 슬롯 | 게임 한 판 전체의 기록. **3개**이며 서로 완전히 다른 게임이다(난이도, 레벨, 스킬트리, 스테이지 기록 모두 따로). 만들 때 난이도를 정하고 이후 바꿀 수 없다 |

## 규칙

1. **일반 스테이지는 웨이브 15단계다.** 보스는 나오지 않는다.
2. **클리어:** 15번째 웨이브의 크립을 모두 내보냈고, 필드에 크립이 하나도 남지 않았을 때(모두 처치되거나 도착).
3. **패배:** 데스가 0이 되면 패배다(현재 규칙 유지: 크립이 도착 지점에 닿거나 필드 크립이 50마리를 넘으면 −1).
4. **클리어 보상:** 스테이지를 클리어할 때마다 보상을 준다. 양은 미정.
   - 처음 클리어: **플레이어 경험치 + 스킬 포인트**
   - 이미 깬 스테이지를 다시 클리어: **경험치만** (스킬 포인트 없음)
5. **스테이지 제한 시간은 없다.** 시간이 오래 걸려도 패배하지 않는다. 별 계산에만 기준 시간이 있다.
6. **정산 후 이동:** 클리어하면 "다음 스테이지" 또는 "메뉴"를 고른다. 패배하면 "다시 하기" 또는 "메뉴"(현재 안).

## 스테이지 선택

참고 이미지: 번호가 적힌 스테이지 칸이 격자로 놓이고, 칸마다 별(0~3개)이 표시된다. 아직 열리지 않은 칸은 자물쇠로 표시한다. 여러 페이지를 좌우로 넘긴다.

- **스테이지 선택 씬을 따로 둔다.** 메뉴 → 저장 슬롯 선택(새로 만들 때 난이도 선택) → 스테이지 선택.
- **순차 해금.** 앞 스테이지를 클리어해야 다음 스테이지가 열린다. 1스테이지는 처음부터 열려 있다.
- 클리어 기록(해금 상태, 별)은 저장 슬롯에 영구 저장한다.
- **보스 스테이지 배치:** 일반 스테이지 3개 다음에 보스 스테이지 1개. **4, 8, 12 … 번**이 보스 스테이지다. 보스 스테이지 규칙은 따로 기획한다.
- 보스 스테이지 규칙은 아래 "보스 스테이지" 절.
- 한 페이지에 15칸(5×3), 좌우 화살표로 페이지를 넘긴다(현재 안, 참고 이미지 기준).

## 별 (0~3개)

별은 **3개에서 시작해 깎인다.**

| 조건 | 별 |
|---|---|
| 기본 | 3 |
| 통과한 크립(도착 지점에 닿은 크립)이 하나라도 있음 | −1 |
| 별 기준 시간 안에 못 깸 | −1 |
| 클리어 못 함 | 0 (클리어 아님) |

- 클리어하면 최소 1개다: 3 − 1 − 1 = 1.
- 별 0개 = 클리어하지 못한 상태다. 다음 스테이지가 열리지 않는다.

- 한 스테이지를 여러 번 깨면 가장 많이 받은 별을 기록한다(현재 안).

## 보스 스테이지

2026-09-26 정의.

1. **웨이브 구성:** 1~14웨이브는 일반 스테이지와 같이 크립만 나온다. **15번째 웨이브에는 크립과 보스가 함께** 나온다.
2. **보스의 특징:** 일반 크립보다 **크고 느리다**. 대신 **HP가 많다**.
3. **보스는 1기.**
4. **보스를 잡으면 그 즉시 클리어.** 필드에 크립이 남아 있어도 스테이지가 끝난다. 보스를 잡아야만 클리어할 수 있다.
5. **보스가 도착점에 닿으면 스테이지 실패**(별 0).
6. 보스 처치 보상은 아직 계획하지 않았다.

현재 수치 (임시, `MobDefs.BossDefFor(15)`):

| | 일반 크립 (15웨이브) | 보스 |
|---|---|---|
| 크기 | 1.0~1.4배 | 2.2배 |
| 속도 | 약 66~124 px/s (종류별) | 55 px/s (가장 느린 크립보다 느림) |
| HP | 기준 HP × 0.7~1.6 | 기준 HP × 7 (2026-09-27 20 → 7, 약 1/3) |

구현 (2026-09-26): 15번째 웨이브에 보스가 맨 먼저 나오고 크립이 뒤따른다. 보스를 잡으면 즉시 클리어, 보스가 도착하면 실패.

## 난이도

쉬움 / 보통 / 어려움. 난이도가 오를수록 크립의 **HP**와 **수**가 늘어난다.

- **저장 슬롯을 만들 때 한 번 정한다.** 이후에는 바꿀 수 없고, 다른 난이도로 하려면 새 저장 슬롯을 만들어 처음부터 한다.
- 따라서 별·해금 기록은 저장 슬롯 하나에 한 벌이다(난이도별로 따로 둘 필요가 없다).

## 스테이지별 차이

- 스테이지마다 **맵**(시드·나무 배치)이 다르다.
- **조명(모든 스테이지 씬 공통):** 주변광은 그라디언트(하늘 푸른빛·수평선 회색빛·땅 풀빛), 해 그림자 진하기 0.75. 스카이박스 주변광은 조명을 굽지 않아 비어 있어 해를 등진 면이 새까매지므로 쓰지 않는다(2026-09-27).
- 스테이지마다 **크립 종류**가 달라지고, 뒤로 갈수록 **크립이 강해진다**.
- 크립 속도는 크립 종류별 기획에서 정한다(별도 문서).

## 크립 구성과 강도

2026-09-27 정의. 조사 자료: [CREEP_HP_RESEARCH.md](CREEP_HP_RESEARCH.md). **킹덤러쉬식 "스테이지마다 다른 크립"을 기본으로 하고, 숫자 공식은 보조로 섞는다.**

### 크립 풀 (킹덤러쉬식)

1. **스테이지마다 나오는 크립 종류(풀)를 정한다.** 웨이브별 구성은 손으로 짜지 않는다.
2. **한 웨이브 안에서 풀의 종류가 섞여 나온다.** 웨이브 r의 i번째 크립(0부터) = 풀[(r − 1 + i) % 풀 크기]. 풀을 차례로 돌되 웨이브마다 맨 앞 종류가 바뀐다.
3. **스테이지마다 한 종류씩 늘어난다.**
4. 황금 비둘기(보너스)와 보스는 풀과 따로 나온다.

1~4스테이지는 농장 구역([STORY_ZONES.md](STORY_ZONES.md)).

| 스테이지 | 섞여 나오는 크립 | 새로 나옴 |
|---|---|---|
| 1 | 양 | 양 |
| 2 | 양, 돼지 | 돼지 (분열 → 새끼 돼지 둘) |
| 3 | 양, 돼지, 닭 | 닭 (빠름) |
| 4 (보스) | 양, 돼지, 닭, 소 + 15웨이브 보스 성난 황소 | 소 (방어력), 성난 황소 |

| 크립 | 역할 | HP | 방어 | 속도 | 크기 |
|---|---|---|---|---|---|
| 양 | 기본 | ×1.0 | ×0.8 | ×1.0 | 사람 키 |
| 닭 | 빠름 | ×0.6 | ×0.4 | ×1.45 | ×0.8 |
| 소 | 단단함 | ×1.3 | ×1.7 | ×0.75 | ×1.35 |
| 돼지 | 질김·분열 | ×1.5 | ×0.7 | ×0.85 | ×1.1 (새끼 돼지 ×0.6, 부모 HP 25%, 조금 빠름) |
| 성난 황소 | 구역 보스 | 웨이브 기본 HP ×7 | ×1.2 | 55 | ×2.2 |

- 크립 종류 id·수치·소개 문구는 `MobDefs`(농장 4종 + 도심 3계열 × 3단계), 풀과 구역 보스는 `Resources/Stages.asset`의 `creeps`·`boss`.
- 모델은 크립 종류마다 `Resources/Creeps/<모델>` 프리팹(양·닭·소·돼지·황소, 걷기 애니메이션 포함). Blender 스크립트: `Tools/Blender/make_farm.py` → Unity 메뉴 `TowerDefense/Mobs/Build All Mob Prefabs`.
- **성난 황소 외형** (보스는 실루엣부터 달라야 한다, `make_farm.py`의 `bull()`): 돌진 자세(어깨 혹이 가장 높고 머리는 숙임), 앞이 크고 뒤가 작은 쐐기 몸, 검은 갈기, 옆으로 뻗었다 앞·위로 휜 큰 뿔 + 쇠 띠, 찌푸린 눈썹과 빛나는 붉은 눈, 금 코뚜레, 쇠가시 목줄과 끊어진 사슬(우리를 부수고 나온 황소). 몸 색은 보스 색(`MobDefs`, 0x7a3322).
- 풀이 비어 있는 스테이지는 원본 규칙(웨이브 번호로 계열·단계)을 쓴다.

### 강도 (공식)

- **크립 HP = 웨이브 기본 HP × 크립 종류 배율 × 스테이지 배율 × 난이도 배율.**
  - 웨이브 기본 HP: `18 × 1.18^(웨이브 − 1)` (2026-09-28 1.21 → 1.18. 자동 플레이 테스트에서 15웨이브가 1웨이브의 14배로 튀어 포탑만으로 2·4스테이지를 못 깼다).
  - **스테이지 배율 = 1.15^(스테이지 − 1)**: 1스테이지 1.0, 2스테이지 1.15, 3스테이지 1.32, 4스테이지 1.52 … 스테이지가 늘어도 자동으로 계산된다(`StageRules.StageHpMul`).
- 난이도의 대부분은 **새 크립**이 맡고, 공식은 같은 크립이 뒤 스테이지에서 조금씩 단단해지게 하는 보조다.

### 새 크립 소개 카드

- 저장 슬롯에서 **처음 만나는 크립**이 웨이브에 나오면 화면 왼쪽 위에 소개 카드(이름, 특징)를 5초 띄운다. 보스도 처음 한 번.
- 만난 기록은 저장 슬롯에 남는다(`PlayerProfile.seenCreeps`, 정산 때 저장). 스테이지를 끝내지 않고 나가면 다음에 다시 뜬다.

## 현재 구현과의 차이 (2026-09-24)

| 항목 | 현재 (`Core/WaveSystem.cs`, `GameConfig`) | 바꿀 것 |
|---|---|---|
| 웨이브 수 | 40 (`RoundMax`) | 15 |
| 승리 조건 | 40웨이브 보스 처치 | 15번째 웨이브의 크립을 다 내보내고 필드가 빔 |
| 보스 | 10·20·30·40웨이브 | 일반 스테이지에서는 빼고, 보스 스테이지에서 다룬다 |
| 승리 후 | 무한 모드 가능 | 없음 |
| 난이도 | 메뉴에서 판마다 고름, HP·속도 배율 (`MobDefs.Difficulty`) | 저장 슬롯에 고정, HP와 크립 수 배율 |
| 저장 | 프로필 파일 하나 (`profile.json`) | 저장 슬롯 3개, 슬롯마다 파일 하나 |
| 맵 | Map 씬 하나 | 스테이지마다 맵(시드·나무)과 웨이브 구성 |
| 스테이지 선택 | 없음 (메뉴 → 난이도 → Map) | 메뉴 → 스테이지 선택 → 스테이지 |

## 미정

- **별 기준 시간 값:** 스테이지 데이터에 스테이지별로 둔다. 값은 테스트 플레이로 정한다.
- **클리어 보상 양:** 경험치·스킬 포인트를 얼마나 주는가? (테스트 플레이로 정한다)
- **보스 처치 보상:** 미계획.
- **크립 종류 기획:** 종류별 속도·특징은 별도 문서로 정한다. 스테이지별 등장은 위 "크립 구성과 강도". 5스테이지부터의 풀은 미정.
- 한 웨이브에 여러 종류를 섞을 것인가? (지금: 웨이브당 한 종류)
- 참고 이미지의 상점과 재화는 이번 범위에 넣지 않는다(현재 안).
