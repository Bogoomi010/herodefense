- 스테이지 시스템 구현 계획 추가 (`docs/IMPLEMENTATION_PLAN.md` 하단): 저장 슬롯 → 웨이브 15 클리어·난이도 → 스테이지 데이터·별·보상 → 슬롯·스테이지 선택 화면 → 정산과 이동.
- 스테이지 시스템 구현 (EditMode 테스트 36개 통과, 에디터 플레이 확인):
  - 저장 슬롯 3개 (`save_0~2.json`). 메뉴 "시작" → 슬롯 선택, 빈 슬롯은 난이도를 골라 새로 만듦(이후 변경 불가), 슬롯 삭제는 확인 후.
  - 스테이지 선택 씬: 5×3 칸, 페이지 넘김, 별·잠김·보스 표시, 순차 해금. 스킬트리를 이 화면으로 옮김.
  - 스테이지 = 15웨이브. 마지막 웨이브의 크립을 다 내보내고 필드가 비면 클리어. 스테이지 제한 시간 없음, 원본 40웨이브·무한 모드 제거.
  - 별: 3에서 통과 크립 있으면 −1, 기준 시간 초과 −1 (클리어 최소 1). 정산 후 다음 스테이지 / 다시 하기 / 스테이지 선택.
  - 클리어 보상: 처음 = 경험치 + 스킬 포인트, 다시 = 경험치만.
  - 난이도: 크립 HP(쉬움 0.85 / 어려움 1.25)와 웨이브당 수(0.8 / 1.3배). 스테이지별 HP 배율.
  - 테스트용 스테이지 4개 (`Stage_01`=기존 Map ~ `Stage_04` 보스), `Resources/Stages.asset`, 빌드 순서 MainMenu → StageSelect → Stage_01~04.
  - 보스 스테이지 임시 규칙: 마지막 웨이브에 보스 1기, 보스가 도착하면 실패.
  - 코드 리뷰(서브에이전트) 반영: 슬롯 덮어쓰기 방지, 깨진 저장 파일 처리, 목록에 없는 씬은 기록 안 함, 스테이지 번호는 자기 씬 기준.
